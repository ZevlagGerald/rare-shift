# RARE//SHIFT V2-ART-00 — VISUAL NORMALIZATION QUALIFICATION PROTOCOL

**Status:** ACTIVE — IMPLEMENTATION TRANCHE  
**Branch:** `feature/v2-art00-visual-normalization`  
**Base:** `planning/v2-survivor-restructure@c12e5432a77869b837ebd3b6922dfa21eca788f3`  
**Scope:** visual language, provenance, production-ready sandbox asset kit  

## 1. Purpose

V2-ART-00 establishes the production visual system required before the V2 combat sandbox may be qualified.

This tranche does not implement the complete survival game. It proves that canonical Friend art, environment, enemies, HUD, upgrade cards, pickups and combat FX can coexist as one coherent RARE//SHIFT visual language.

## 2. Locked visual authority

The tranche inherits:

- `docs/governance/RARE_SHIFT_V2_VISUAL_ASSET_GOVERNANCE_v1.md`;
- `docs/design/RARE_SHIFT_V2_ASSET_SOURCE_MATRIX_v1.md`;
- `docs/governance/RARE_SHIFT_V2_MASTER_IMPLEMENTATION_BASELINE_v1.md`;
- `docs/governance/RARE_SHIFT_V2_THREE_CATEGORY_GOVERNANCE_v1.md`.

The selected Rare Friend's canonical artwork remains authoritative and may not be redrawn, recolored, stretched, rotated into a new identity, or replaced by external player art.

## 3. Required production sample set

V2-ART-00 must produce and qualify at least:

1. FRACTURE GRID floor/environment sample;
2. canonical Friend presentation treatment;
3. TRACE enemy;
4. SPLIT-A enemy;
5. SPLIT-B enemy;
6. Signal XP pickup;
7. HP / XP / phase HUD fragment;
8. SHIFT control/prompt;
9. three-card level-up draft UI;
10. DELTA BURST visual proof using canonical `A_ONLY` / `B_ONLY` geometry;
11. SHIFT transition effect;
12. enemy spawn effect;
13. enemy hit effect;
14. enemy death effect;
15. candidate SFX mapping;
16. asset provenance manifest.

## 4. Phase grammar

The established visual lineage remains:

- Phase A: `#4cc9f0` lineage;
- Phase B: `#f72585` lineage;
- COMMON: `#e8edf2` lineage;
- VOID/dark: existing `#0b0e12`, `#11151b`, `#202832` lineage.

Color is reinforcement, not sole authority.

Required non-color cues:

- A: angular / directional / broken-edge language;
- B: offset / flowing / mirrored language;
- COMMON: stable / structural language;
- VOID: quiet / low-emphasis language.

SPLIT-A and SPLIT-B must remain distinguishable in grayscale or low-saturation review.

## 5. External asset policy

Primary source family: Kenney CC0.

Approved candidate families include:

- 1-Bit Pack;
- Input Prompts Pixel 1-Bit;
- UI Pack - Sci-Fi;
- Particle Pack;
- Sci-fi Sounds;
- Impact Sounds;
- Interface Sounds.

OpenGameArt is secondary and every selected source file requires individual license evidence.

No wholesale library/repository import is allowed.

Every admitted source file must record:

- source family;
- original file name/path;
- author/publisher;
- source URL;
- license;
- license evidence URL/reference;
- source SHA-256;
- transformation description;
- production path;
- production SHA-256;
- approval state.

## 6. Normalization pipeline

Every external candidate must pass:

`SOURCE → CROP/CLEAN → SCALE/NORMALIZE → RARE//SHIFT PALETTE → PHASE GRAMMAR → READABILITY REVIEW → PRODUCTION`

Rules:

- nearest-neighbor scaling for pixel primitives;
- no mixed-pixel-density appearance;
- no conflicting outline language;
- no recognizable stock-pack visual that dominates the canonical Friend;
- phase variants should be generated from one normalized base where practical;
- production assets may not silently reference vendor paths.

## 7. Signature effect rule

The following are RARE//SHIFT identity effects and must not be replaced by generic stock animation:

- DELTA BURST;
- RECONSTRUCTION FIELD;
- SHIFT transition.

External CC0 particle textures may support them, but geometry/timing/composition must be generated by our game and canonical Friend data.

## 8. UI rules

HUD and upgrade cards must:

- remain readable inside the FriendSDK 960×640 game frame;
- survive the narrow-phone host around 390px;
- avoid generic dashboard styling;
- reserve combat visibility around the player;
- expose phase state without relying only on color;
- use large touch targets;
- remain usable with reduced motion.

The three-card draft must show, at minimum:

- item name;
- current/next rank or acquisition state;
- concise behavior description;
- weapon/protocol category;
- EVO relationship when applicable.

## 9. Combat readability requirements

A static and moving sandbox proof must demonstrate:

- canonical Friend remains visually dominant and readable;
- TRACE is distinct from SPLIT-A/B;
- SPLIT-A and SPLIT-B are distinguishable without color alone;
- Signal XP remains visible against FRACTURE GRID;
- DELTA BURST does not obscure enemy telegraphs;
- SHIFT transition communicates state change without long visual lockout;
- spawn/death FX do not resemble live hazards;
- HUD does not cover critical playfield information.

## 10. Performance constraints

V2-ART-00 may not admit an effect solely because it looks good in isolation.

Candidate effects should favor:

- pooled particles;
- bounded particle counts;
- atlas/small texture reuse;
- procedural geometry;
- limited overdraw;
- no mandatory full-screen blur;
- reduced-motion fallbacks.

Exact mobile limits are established in V2-1 stress qualification.

## 11. Asset manifest

Canonical manifest path:

`games/rare-shift/assets/ASSET_MANIFEST.json`

The manifest is evidence, not merely credits. Production admission requires valid provenance entries and hashes for external source assets.

Generated/procedural assets must still document their generator/source authority and production path.

## 12. Acceptance gates

V2-ART-00 may close only when:

- all required sample-set items exist or are explicitly procedural with a working proof;
- canonical Friend art is unchanged;
- phase grammar is consistent across environment/enemy/UI/FX;
- source provenance is complete for all external assets;
- no ambiguous-license asset is present;
- 960 visual review passes;
- narrow-host visual review passes;
- reduced-motion treatment is defined;
- no critical HUD/playfield overlap is present;
- asset files are bounded to the approved production set;
- no gameplay/economy scope has leaked into the tranche.

Decision gate:

`V2_ART_00=PASS`

- complete weapon roster implementation;
- boss artwork;
- full seven-minute game;
- RF economy runtime;
- multiplayer/backend;
- main merge;
- production deployment;
- Vibeathon submission.
